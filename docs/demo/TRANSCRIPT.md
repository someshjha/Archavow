# Archavow final walkthrough

The animated walkthrough is approximately 27 seconds and uses the real local Archavow application.

> Note: re-record the GIF/MP4 and `demo-poster.png` after the ArchFoundry → Archavow rename if the chrome still shows the old brand.

## 00:00 — Start with evidence

Create the claims-adjudication initiative with its objective, current problem, ten business requirements, scale targets, and technology constraints. Requirements receive stable `R-001–R-010` references before architecture generation.

## 00:04 — Close the important gaps

The focused interview asks only for missing evidence. Coverage states (`missing` / `partial` / `evidenced` / `verified`) and human gates stay visible beside the conversation instead of disappearing into chat history.

## 00:08 — Compare real trade-offs

Review three tailored alternatives with assumptions, constraints, decisions, benefits, drawbacks, cost, operational burden, and fit. Origins show AI vs deterministic template. A human selects the architecture.

## 00:11 — Generate one coherent package

The selected option becomes a browsable architecture package (one artifact at a time, catalog order). Walk overview through HLD, ADRs, risks, threats, the evidence checklist, roadmaps, both backlogs, and the review record.

## 00:15 — Inspect live diagrams

Review rendered Mermaid diagrams across C4 levels 1–3, sequence, and labeled data flow.

## 00:19 — Trace requirements into delivery

Business epics and user stories cite the requirement they came from (`evidence_derived`). Technical enablers remain separate (`baseline_recommendation`) and are labeled as baseline—not customer requirements.

## 00:23 — Export a Git-ready record

Select the package contents and download portable Markdown, Mermaid, decisions, risks, evidence checklist, delivery backlog, and project JSON. README lists artifacts in catalog order (`mvp.v2`).
